This is a multi-page website built with **HTML, CSS, and vanilla JavaScript**, plus a small Node.js development server and Vercel API functions. Supabase provides the hosted authentication and PostgreSQL/realtime services needed for real accounts and messages. ## Project structure ```text DecisionWise/ ├── public/ # Website pages and browser assets │ ├── index.html # Homepage │ ├── how-it-works.html │ ├── categories.html │ ├── decision.html │ ├── accounts.html │ ├── messages.html # Real direct-messaging interface │ ├── about.html │ ├── languages.html │ ├── login.html # Sign up and sign in │ ├── 404.html │ ├── css/style.css │ └── js/ │ ├── main.js │ ├── supabase-config.js # Add Supabase project URL + public anon key here │ ├── auth-app.js │ └── messages-app.js ├── supabase/messaging.sql # Database schema, functions, RLS, realtime ├── api/status.js # Vercel status function ├── api/translate.js # Vercel Google Cloud Translation function ├── local-server.js # Local development server ├── package.json ├── vercel.json ├── .env.example └── README.md ``` ## What is implemented - Responsive multi-page interface and shared styling. - Sign-up and sign-in using Supabase Auth (passwords are handled by Supabase, not stored by this site). - Profile creation and user search by display name/username. - One-to-one conversations stored in Supabase PostgreSQL. - Realtime incoming message subscriptions while a conversation is open. - Database Row Level Security (RLS) policies and restricted database functions. - Light/dark theme controls and the existing decision workspace UI. - Optional server-side translation API for English, French, and Kinyarwanda; Google Cloud Translation must be configured separately. ## Required setup for real accounts and messages The code cannot connect to your database until you configure a Supabase project. There is no fake/localStorage messaging fallback. 1. Create a project at https://supabase.com/. 2. In the Supabase dashboard, open **SQL Editor → New query**. 3. Open `supabase/messaging.sql`, copy the entire file into the editor, and run it. Resolve any SQL error before continuing. 4. Open Supabase **Project Settings → API** (or API Keys). Copy the Project URL and the **anon/public** key. 5. Edit `public/js/supabase-config.js` and replace the two placeholder values: ```js window.DECISIONWISE_SUPABASE_URL = "https://YOUR_REAL_PROJECT_ID.supabase.co"; window.DECISIONWISE_SUPABASE_ANON_KEY = "YOUR_REAL_SUPABASE_ANON_KEY"; ``` The anon/public key is designed for browser use when RLS is enabled. **Never use the `service_role` key or database password in browser code.** 6. In Supabase **Authentication → URL Configuration**, allow `http://localhost:3000` for local testing. Later add your exact Vercel domain. 7. In **Authentication → Providers → Email**, check whether email confirmation is enabled. If it is, users must verify their email before signing in. ## Run locally in VS Code on Windows Install Node.js 18 or newer first: https://nodejs.org/. 1. Extract this ZIP. 2. Open the extracted `DecisionWise` folder in VS Code (the folder containing `package.json`). 3. Choose **Terminal → New Terminal**. 4. Run: ```bash npm install npm start ``` 5. Open `http://localhost:3000/login.html`. 6. Create two test accounts using email addresses you control. If email verification is enabled, verify both. 7. Sign in as user A, open Messaging, search for user B's display name or username, and send a message. Open a second browser profile and sign in as user B to verify persistence and live delivery. To check JavaScript syntax after installing dependencies, run `npm run check`. ## Deploy to Vercel 1. Create a GitHub repository and upload the **contents** of this project folder. Do not upload `.env` files, passwords, or service-role keys. 2. In https://vercel.com/, select **Add New → Project** and import the repository. 3. Use the folder containing `package.json`, `vercel.json`, `api/`, and `public/` as the project root. The output directory is set to `public`; use no frontend build command. 4. Deploy. Add the resulting domain to Supabase **Authentication → URL Configuration**. 5. Open `https://YOUR-VERCEL-DOMAIN/login.html` and test with two accounts. 6. For translation, set `GOOGLE_TRANSLATE_API_KEY` in Vercel Project Settings → Environment Variables, enable the Google Cloud Translation API, configure billing if required, and redeploy. Never put this key in browser JavaScript. ## Honest limitations - Real accounts and messaging require the Supabase setup above; placeholders intentionally prevent connection until configured. - Messages are direct one-to-one messages. Group chats, attachments, editing/deleting, read receipts, typing indicators, blocking/reporting, and moderation are not implemented. - The decision workspace is an interface starter; a complete AI-powered decision-analysis engine is not implemented yet. - Translation only works after the provider key/API is configured and currently applies only to supported UI text; it does not automatically translate all user-generated messages. - This project has not had an independent penetration test. Do not use it for confidential government, medical, legal, or emergency case communications until it has a professional security and privacy review. ========================================================================================== FILE: api/status.js ========================================================================================== export default function handler(_req, res) { res.setHeader("Cache-Control", "no-store"); A structured process

Understand the situation before selecting a solution.

DecisionWise organizes the questions to consider; people remain responsible for verifying facts and choosing what to do.

01

Describe the context

Clarify what is happening, what matters, what is known, what is uncertain, and which constraints cannot be ignored.

02

Define the desired outcome

State what a useful result looks like, including priorities, deadlines, resources, and acceptable trade-offs.

03

List realistic alternatives

Include more than one path where possible, including waiting, gathering evidence, or combining approaches.

04

Compare consequences

Consider benefits, costs, risks, feasibility, fairness, affected people, reversibility, and longer-term effects.

05

Review and decide

Check assumptions, identify missing information, document reasons, and decide whether expert advice or team discussion is needed.
